## I. Document Overview

This document outlines the common uses of `docker cp` in Docker, focusing on:

- Copying files from a container to the host
- Copying files from the host to a container
- Copying files from a stopped container
- Copying directories
- Key points regarding path notation
- Using container names or IDs
- File permission issues
- Why `docker cp` is not suitable for large-scale data migration

The goal is to:

- Be able to retrieve configurations from containers
- Access logs within containers
- Temporarily add files to containers
- Understand the limitations of `docker cp`

## II. Basic Usage of docker cp

---

## Scenario 20: Copying Files from a Container to the Host

### Command

```bash
docker cp container-ID:/path-in-container /path-on-host
```

### Example

```bash
docker cp nginx:/etc/nginx/nginx.conf /root/
```

### Explanation

- Copies files from inside the container to the host.
- Common uses include:
  - Retrieving configuration files
  - Accessing logs
  - Troubleshooting issues

---

## Scenario 21: Copying Files from the Host to a Container

### Command

```bash
docker cp /path-on-host container-ID:/path-in-container
```

### Example

```bash
docker cp /root/nginx.conf nginx:/etc/nginx/nginx.conf
```

### Explanation

- Copies files from the host to the container.
- Useful for:
  - Temporarily modifying configurations
  - Fixing file issues
  - Injecting scripts into containers

---

## Scenario 22: Copying Files Even When the Container Is Not Running

### Note

```text`
docker cp does not depend on the container's running status.
```

In other words:

```text
Files can still be copied from a stopped container.
```

### Explanation

As long as the container object exists, `docker cp` can be used to copy files regardless of whether the container is running. This is particularly useful when troubleshooting failed containers, such as those that exit immediately after starting or cannot be accessed via a shell.

---

## Scenario 23: Copying Directories

### Example

```bash
docker cp nginx:/var/log/nginx /root/nginx-log
```

### Explanation

This command copies the `/var/log/nginx` directory inside the container to the `/root/nginx-log` directory on the host.

Common applications include:

- Copying log directories
- Moving configuration folders
- Storing temporary troubleshooting files
- Archiving files generated by running applications

## III. Common Points to Note

---

## Scenario 24: Common Issues and Solutions

### 1. Paths Must Be Fully Specified

Incorrect example:

```bash
docker cp nginx:nginx.conf /root/
```

Correct example:

```bash
docker cp nginx:/etc/nginx/nginx.conf /root/
```

### Explanation

It is recommended to use absolute paths when specifying container paths. The incorrect version lacks clarity and may lead to file not being found or misinterpreted.

---

### 2. Container Names Can Also Be Used

```bash
docker cp nginx:/etc/nginx/nginx.conf /root/
```

### Explanation

`docker cp` does not necessarily require the use of a container ID; you can also use the container name instead. For example, if the container name is `nginx`, you can simply write:

```bash
docker cp nginx:/etc/nginx/nginx.conf /root/
```

This makes it more intuitive than using a container ID.

---

### 3. Permission Issues After Copying

The ownership of copied files may change. You may need to adjust permissions manually:

```bash
chown
```

```bash
chmod
```

### Example

Changing file ownership:

```bash
chown root:root /root/nginx.conf
```

Adjusting file permissions:

```bash
chmod 644 /root/nginx.conf
```

### Explanation

After copying files from a container to the host, you might encounter issues such as:

- The file not belonging to the expected user
- Inappropriate file permissions
- Ordinary users being unable to read the file
- Service processes being unable to access the file
- Excessively permissive file permissions posing security risks

Therefore, it is essential to check and adjust permissions according to your specific use case.

---

### 4. Not Suitable for Large-Scale Data Migration

Reasons:

- `docker cp` is designed for temporary operations.
- It is not suitable for long-term data synchronization or handling large volumes of data.

Recommendation:

```text
Using volume/mounting methods is more appropriate.
```
