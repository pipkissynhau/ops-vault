```nginx

```nginx

    server 10.0.0.11:8080;

}
```

Answer:
Common load balancing algorithms in Nginx include:

1. **Round Robin**: The default algorithm that distributes requests equally among available servers.
2. **Weighted Round Robin**: Assigns more weight to servers based on their performance or capacity.
3. **ip_hash**: Distributes requests based on the client's IP address.
4. **least_conn**: Assigns requests to the server with the fewest active connections.

## 19. What is Prometheus?
Answer:
Prometheus is a monitoring system that processes time-series data.  
It regularly collects metrics exposed by exporters and stores them as time-series data.  
Based on predefined alarm rules, it determines whether any anomalies exist; if alarms are triggered, Alertmanager handles the grouping, deduplication, and notification of these alerts.  
Grafana is often used to visualize the monitoring data through dashboards.

---

## 20. What is the overall workflow of Prometheus?
Answer:
The process involves:
- The monitored objects expose their metrics via exporters.
- Prometheus periodically retrieves these metrics using a pull mechanism.
- The metrics are stored as time-series data for analysis.
- Alerts are generated based on predefined rules, and Alertmanager handles notification.
- Grafana provides visualizations for the collected data.

---

## 21. What is the role of exporters in Prometheus?
Answer:
Exporters convert the status of monitored services into a format that Prometheus can understand.  
Common examples include `node_exporter` for Linux hosts and `mysqld_exporter` for MySQL databases.

### Examples of exporters

- mysqld_exporter

## 22. Why is Prometheus called a pull-based system?
Answer:
In Prometheus, it is not the monitored objects that push data to Prometheus; instead, Prometheus actively retrieves data from the specified `/metrics` endpoint of these objects.

## 24. Where are monitoring rules and alarm settings defined?
Answer:
Monitoring targets and configuration details are typically specified in the `prometheus.yml` file, particularly within the `scrape_configs` section.  
Alarm rules are usually stored in separate files, such as `rules/*.yml`, which are then referenced in `prometheus.yml` using the `rule_files` setting.  
When Prometheus detects a rule violation, it triggers the specified alert mechanism, such as sending notifications via DingTalk or email.

### Example of prometheus.yml
    global:
      scrape_interval: 15s

    rule_files:
      - "rules/*.yml"

    alerting:
      alertmanagers:
        - static_configs:
            - targets: ['10.0.0.20:9093']

    scrapeConfigs:
      - job_name: 'node'
        static_configs:
          - targets: ['10.0.0.11:9100', '10.0.0.12:9100']

### Example of alarm rule file rules/node_rules.yml
    groups:
    - name: node-alerts
      rules:
      - alert: HostHighCPU
        expr: 100 - (avg by(instance)(rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100) > 80
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "Host CPU usage is too high"
          description: "{{ $labels.instance }} has had a continuous CPU usage of over 80% for 5 minutes"

### Example of alertmanager.yml
    route:
      receiver: 'default'

    receivers:
    - name- source_labels: [__meta_kubernetes_pod_annotation/prometheus_io_path]
            action: replace
            target_label: __metrics_path__
            regex: (.+)

          - source_labels: [__address__, __meta_kubernetes_podannotation/prometheus_io_port]
            action: replace
            regex: ([^:]+)(?::\d+)?;(\d+)
            replacement: $1:$2
            target_label: __address__

### Example Pod annotations required for cooperation
    annotations:
      prometheus.io/scrape: "true"
      prometheus.io/port: "8080"
      prometheus.io/path: "/metrics"

## 39. What is the purpose of the sort command?
Answer:
The sort command is used to arrange text data in a specific order. By default, it sorts the data alphabetically by character.

### Examples
    cat access.log | sort
    sort /etc/passwd
    sort -n numbers.txt

### Common options
- -n: Sorts data numerically.
- -r: Sorts data in reverse order.
- -k: Sorts data based on a specified column.

### Example
    sort -t ':' -k 3 -n /etc/passwd

---

## 40. What is the function of the uniq command?
Answer:
The uniq command is typically used in conjunction with the sort command to remove duplicate lines or count the number of unique lines in a file.
Since uniq can only identify consecutive duplicate lines, it is usually applied after sorting the data first.

### Examples
    cat ip.log | sort | uniq
    cat ip.log | sort | uniq -c

### Common options
- -c: Counts the number of occurrences of each unique line.
- -d: Displays only duplicate lines.
